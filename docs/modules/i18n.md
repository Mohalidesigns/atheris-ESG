# Interface languages (WP-45)

Decision: [D45](../esg-completion/DECISIONS.md). Requirements: BRD-5.2.4-04, BRD-7.6-02, BRD-7.6-03.

## What it does

The interface is available in English (source), French, Portuguese, Arabic (right to left), Swahili, Hausa and Yoruba.
People choose the language on the sign-in page or in the account menu; signed in, the choice is stored on their account
(`auth.users.preferred_language`) and applied on every device. Numbers, money, percentages and dates follow the
language's locale.

The six translations are **machine drafts** that a professional translator has not reviewed. Each bundle's `meta`
says so (`status: "draft"`, `reviewedBy: null`), and the language picker shows "Draft translation".

## How it works

| Part | Where |
|---|---|
| `tr(text, values?)`: the English text is the key; it returns the current language's text, or the English text when there is none. Interpolation runs only when values are passed. | `esg-frontend/src/i18n/index.js` |
| `setLanguage(code)`: loads the bundle on demand, switches i18next, sets `<html lang dir>` and remembers the choice on the device | same |
| Formatting: `formatNumber`, `formatCurrency` (narrow symbols), `formatPercent`, `formatDate`, `formatDateTime`; `formattingLocale()` for direct `Intl` use | `src/i18n/format.js` |
| RTL: MUI theme direction plus an emotion cache with `stylis-plugin-rtl`; children re-render when the language changes | `src/i18n/LanguageRoot.jsx` |
| Picker (sign-in page and account menu) and the account-language hook (applies the account's choice at sign-in; saves a first device choice to the account) | `src/components/i18n/` |
| Saving the choice: `PUT /api/v1/auth/me/language` `{ "preferredLanguage": "fr" }` (any signed-in user, own account; `en, fr, pt, ar, sw, ha, yo`) | `AuthController`, `AuthService.setLanguage` |
| Bundles: `src/i18n/locales/<code>.json` = `{ meta, messages }`; `status.json` holds coverage per language | generated |

## Adding or changing interface text

1. Write English text inside `tr("…")`, or in a `label` / `title` / `description` / `hint` / `message` / `text` /
   `header` field, or as a value of an UPPER_CASE label map (`const STATUS = { open: 'Open' }`), rendered as
   `tr(STATUS[s])`. ESLint (`i18next/no-literal-string`) flags bare JSX text; `npm run i18n:wrap` wraps text in bulk.
2. Run `npm run i18n:extract`. New texts are added to every bundle as empty (shown in English) and coverage drops.
3. Add the translations to each bundle, then re-run the extract. CI runs `npm run i18n:check`, which fails when a
   bundle is out of step with the source.

Don't build sentences by joining translated fragments when you can avoid it. Use one text with values:
`tr('{{n}} waiting', { n })`.

## Not translated (yet)

- Messages from the server (validation and RFC 7807 errors).
- Catalogue content (metric, framework and factor names).
- Text built inside template strings, and labels made from codes (`humanize`).
- Generated reports and PDFs.

## Tests

- `src/i18n/i18n.test.jsx` covers the fallback, the French bundle, interpolation, `dir=rtl`, the device choice, the
  formatters, and the picker (saves to the account when signed in, local only when signed out).
- `LanguagePreferenceTest` covers save and reload via `/auth/me`, an invalid value (400) and signed out (401).
- Cypress `journey-28-language.cy.js`:
  1. French is chosen on the sign-in page and the form is used in French.
  2. The menu is in French and the choice is saved on the account.
  3. A device with no saved choice starts in French.
  4. Arabic turns the page right to left and passes axe WCAG 2.1 AA.
  5. Switching back to English works.
